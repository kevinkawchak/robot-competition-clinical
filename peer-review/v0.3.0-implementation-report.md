## Details Per Fix

### Fix 1: GitHub Pages Path Portability (HIGH)

Both HTML viewers now include a cross-navigation banner at the top.
Links are generated using `window.location.pathname` to derive the
repository base path, making them work for forks and non-default
GitHub Pages configurations.

- Root viewer: shows "v0.1.x Single Station (current) | v0.3.0 Competition"
- v2 viewer: shows "v0.1.x Single Station | v0.3.0 Competition (current)"

### Fix 2: Payload Versioning (HIGH)

All occurrences of `"version": "2.0.0"` changed to `"version": "0.3.0"`
in `run_competition.py` and `export_competition.py`. This aligns the
exported schema version with the project's semantic version stream.

### Fix 3: Terminal Frame (HIGH)

`simulation/export_animation.py` now appends a deterministic final
keyframe at exactly `t = TOTAL_DURATION` if the last generated frame
doesn't reach that timestamp. This guarantees the animation data ends
at the documented total duration.

### Fix 4: PpoConfig Typing (MEDIUM)

Added a dedicated `PpoConfig(TypedDict)` in `simulation_v2/constants.py`
with properly typed fields including `str` for architecture and `int` for
training_episodes. `CompetitionResult.ppo_config` now uses `PpoConfig`
instead of `dict[str, float]`.

### Fix 5: JSON Upload Validation (MEDIUM)

The v2 viewer's upload handler now validates that the parsed JSON
contains a `stations` array and that each station entry has expected
fields before applying the config. Invalid uploads log a warning
instead of silently failing.

### Fix 6: Export Boundary Tests (MEDIUM)

New test file `tests/test_exports.py` with 14 tests covering:
- Required payload fields for both v1 and v2 exports
- Version string format and alignment
- Non-empty keyframe arrays
- Terminal frame presence at expected duration
- Winner validation against station IDs
- PPO config required keys
- Rank assignment completeness

### Fix 7: Refactor Monolithic Viewer (MEDIUM) — Deferred

The viewer scripts remain as single HTML files. Rationale: the
zero-build, single-file deployment model is a core feature for
GitHub Pages. Splitting into modules would require a build step
or complex import map configuration. This is a maintainability
improvement that can be done in a future release if the codebase
grows significantly.

### Fix 8: Standardize Release Metadata (MEDIUM)

- All exports use `"version": "0.3.0"` matching `pyproject.toml`
- README, changelog, and releases consistently reference the same
  version numbering scheme
- Schema version and project version are now unified

### Fix 9: Smoke Command Docs (LOW)

README now includes a "Running Tests and Linting" section with
`pytest tests/ -v`, `ruff check .`, and `ruff format --check .`
commands for contributors.

### Fix 10: v2 Viewer Architecture Map (LOW)

Created `docs/diagrams/v2_architecture.md` archiving the v0.2.0
diagrams. The main README contains updated v0.3.0 diagrams including
the new closable UI panels and final results overlay.

## Additional Improvements (Beyond Peer Review Scope)

These were implemented alongside the peer review fixes based on
the v0.3.0 build prompt requirements:

1. **Complete v2 viewer rebuild**: Removed divider boxes that were hiding
   stations, rewrote the entire 3D scene layout
2. **Closable panels**: Phase timeline and scoreboard are toggle-based
   instead of always-visible, preventing overlap
3. **Final results overlay**: Clear 1st/2nd/3rd/4th display when
   competition ends
4. **Injection target marker**: Red dot on each patient's deltoid
5. **Mobile optimization**: Three responsive breakpoints (768px, 420px)
6. **Full clickable URLs**: README shows complete GitHub Pages URLs
7. **Finish-order tracking**: Stations track the order they complete
